INTERACTION / RESPONSIVE NOTES

Keyboard, motion, and narrow reflow contract

Design evidence only

Focus and keyboard

Skip link focuses #main-content with tabindex=-1. Logical order is header → primary links → selected context → rail → capture → recall → inspector. Native fields and buttons keep visible focus; retry does not steal focus. A real dialog, if added for discard, must use contained focus, Escape/backdrop rules, and restore focus to its opener.

Status and recovery

Capture statuses are local to Capture. Recall partial, error, and recovery statuses are local to Recall with role=status/role=alert. Retry preserves note, query, locator, scope, selected version, and current revision. No application behavior is claimed.

Responsive and keyboard input

At 1440px use rail + task canvas + inspector. At 1024px inspector moves below the canvas. At 390px and 320px tabs scroll, forms stack, result rows stack, IDs wrap, and action groups stay full width. Production should apply safe-area insets and keep the focused field visible while the on-screen keyboard resizes the viewport.

44px, reduced motion, forced colors

Important controls, fields, links, and buttons are at least 44px. prefers-reduced-motion: reduce removes transitions and heartbeat intent while retaining labels and coverage. forced-colors: active switches to system colors, keeps borders/focus/status words, and does not rely on color alone. Light/dark/system share semantic tokens through the root attribute.
